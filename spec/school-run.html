School Run Carpool App

A phone-friendly web app where parents arrange school drop-offs and pick-ups by sharing rides with approved parent drivers, and follow the trip live on a map until their child is handed over and confirmed.

01

Overview and goals

What we are building, and how we will know it worked. Measured at the final demo.

G1

A parent can get set up and book fast

2 test parents each sign up, join a school, add a child and request a seat in 10 minutes or less

G2

A driver can offer and accept rides fast

1 approved test driver posts an offer and accepts a request in 5 minutes or less

G3

The live trip is trustworthy

In 3 real trips of at least 10 minutes, the parent's screen shows the vehicle position within 15 seconds for at least 90% of the trip, and shows "Location lost" whenever updates stop

G4

Children's data and location stay protected

0 cross-family data leaks in the security review; every database rule has an automated test and all pass; no location history is kept after a trip

G5

It works on a phone for everyone

0 critical or serious issues in an automated accessibility scan; every key screen usable at 360 px wide; the app can be added to the home screen

Users and journeys

Who uses the app, and three key journeys.

Visitor

Not signed in

See the landing page and privacy notice; sign in; sign up

Parent

A parent or guardian in a school group

Add children; browse offers; request seats; follow their child's live trip; report a problem

Driver

A parent approved by an admin

Everything a parent can do, plus post offers, accept requests, run trips and share live location

Admin

School staff or the team (a few accounts set by hand)

Create the school and invite code; approve or revoke drivers; read incident reports

Receiving adult

Whoever meets the child at drop-off (no account)

Enters the 4-digit code on the driver's phone to confirm the hand-over

Key journeys

ParentSign up→Verify email→Join the school with the invite code→Add my child→Browse offers→Request a seat→Give the drop-off code to the receiving adult→Watch the live trip→See "Dropped off, confirmed"
DriverApply to drive→Wait for approval→Post a trip offer→Accept a seat request→Start the trip→Mark each pick-up→Enter the drop-off code→Finish the trip
AdminCreate the school and invite code in the console→Review a driver application→Approve it with an expiry date→Read an incident report

Static pages that can be added to a phone's home screen, plus Firebase sign-in and database. The security rules are the real gatekeeper.

Phone or desktop browser

⇄Firebase SDK

Firebase project (new, dedicated)

  • Authentication: email and password, email check
  • Realtime Database with security rules
  • Map tiles from OpenStreetMap, drawn with Leaflet

Why the trip data is split into several paths: database rules grant access to a whole path and do not filter, so each parent can only read their own child's node and the vehicle position, never another family's.

06

Rides, trips and quality

The exact ride and trip rules, the status model, the limits, and how each layer will be tested, including a field trial on real phones.

How rides and trips workseats, start window, location updates, drop-off code, time estimate
  1. Visibility: offers, schools and invite-code joins work only inside one school.
  2. Requests: one active request per child per date and direction. A request needs an open offer with seats left that has not started.
  3. Seats: seats left = seats minus accepted children. It is changed only by the driver's accept and by cancellations, and never goes below 0.
  4. Start window: a driver can start from 60 minutes before to 120 minutes after the offered time, only while approved and within validUntil, and only with at least one accepted child.
  5. Location updates: at least every 15 seconds while moving and every 30 seconds when still. Only the latest point is stored and it is removed when the trip ends.
  6. Location lost: no point for 60 seconds. Parents see the last-seen time.
  7. Time estimate: straight-line distance from the vehicle to the child's stop divided by an assumed 30 km/h, shown as "about N min (estimate)". Under 0.3 km it shows "Arriving now". If the position accuracy is worse than 200 m it says "approximate".
  8. Drop-off code: a 4-digit code made when the request is created and shown only to the parent. The driver's app compares what the receiving adult types with a stored hash. 3 wrong tries unlock "Call parent" and the override with a reason.
